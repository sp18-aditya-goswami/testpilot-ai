Test an API without writing the tests.

An AI test planner for REST APIs. The AI plans the tests and explains failures; code runs every request and decides pass or fail.

01The problem

Slow to write

Writing API tests is daily work, and every endpoint needs its own Postman scripts or pytest cases, written by hand.

Business rules get missed

Schema checks get written; rules like “email must be unique” or “users edit only their own account” often go untested until a bug reaches staging.

AI chat is manual

Claude, ChatGPT and other LLMs can draft tests, but it is prompting and copy-paste: no flow, no record, no reliable pass or fail.

02What TestPilot AI is

A web app that turns an OpenAPI spec and your business rules into a reviewed, runnable test plan, in four guided steps.

1

Your API

Paste the spec link and the server to test.

2

What to test

Choose the endpoints, focus, depth and business rules.

3

Review plan

See every case, who made it and why. Edit before anything runs.

4

Results

A readable report of what to fix, with a suggested fix.

AI plans and explains. Code runs every request and decides pass or fail.

03Key capabilities

Signs itself in

Finds sign-up and login in the spec and gets its own token. Asks for a login or token only when it has to.

Tests with two users

A second test user tries to read, change or delete the first user’s data. Any success is a finding.

Three sources of cases

AI cases from your rules, schema cases from the spec and optional fuzzing, each labelled with who made it.

Review before it runs

See every case before anything is sent. Edit, remove, or ask the AI for more in plain English.

A report built for fixing

One row per root cause with the request, response, checks and likely cause. Show fix adds steps and code.

Works with several AI providers

Pick the provider in Settings; it powers planning, explanations and fixes.

04Why you can trust the results

  • Code decides pass or fail from status codes, the documented schema and response time. The AI never does.
  • Every AI case is checked against the spec before it can run; invalid drafts are rejected with a reason.
  • Secrets stay hidden. Tokens and passwords are masked in every request, response and report.
  • Safe by default. Requests go only to allowed test servers, within a request budget per run.
  • Nothing is deleted by surprise. Delete requests run only when you allow them.
  • Every case explains itself. Each one records who made it and why, so a failure can be traced.
